# Sauvegardes sur Android et TV · SHOW+ Player 1.0.44

Dans l’espace client, ouvrir **Sauvegardes**. Dans SHOW+, aller dans **Paramètres → À propos** sur TV, ou **Paramètres → Informations et maintenance** sur téléphone et tablette. Dans la carte **Sauvegardes**, choisir **Afficher un code de liaison** et saisir le code sur le site. Sur mobile, le code peut être copié et l’espace client ouvert directement. Le code expire au bout de cinq minutes et ne sert qu’une fois. La limite de l’accès Premium s’applique à tous les appareils associés.

Une sauvegarde capture les réglages du profil ouvert sur l’appareil source. La restauration les remplace sur l’appareil de destination. La copie capture les réglages actuels de la source sans créer une sauvegarde permanente. Une TV, un téléphone et une tablette peuvent être utilisés comme source ou destination. L’appareil doit avoir SHOW+ ouvert pour traiter la demande. Le tableau d’activité distingue l’attente de la source et celle de la destination ; une demande expire après 24 h.

Le mode **réglages seuls** couvre l’apparence, l’accueil, le catalogue, la navigation, la lecture, l’audio et les sous-titres. L’option **Inclure les données de la playlist ouverte** ajoute les groupes personnalisés et leurs chaînes, les catégories visibles, les favoris, la liste « À voir » et l’historique (dont la reprise des films et épisodes). Une sauvegarde de profil se restaure sur la même playlist. Les connexions aux playlists, liens privés, clés, PIN et réglages propres au matériel restent sur chaque appareil.

- Pour modifier une sauvegarde de profil, choisir **Organiser les groupes** : renommer, réordonner ou épingler les groupes existants. La restauration applique ces modifications sur l’appareil de destination. La création des groupes et la sélection de leurs chaînes se font depuis SHOW+.
- **Exporter** télécharge un fichier JSON que le compte peut réimporter. Les fichiers restent hors du site une fois téléchargés ; ils peuvent contenir l’historique et les favoris.
- La **synchronisation automatique** est à sens unique entre deux appareils. Elle se configure pendant que les profils souhaités et la même playlist sont ouverts. Si l’un change, la synchronisation se met en pause. La source est vérifiée environ toutes les 15 minutes quand SHOW+ est ouvert, et un état déjà appliqué n’est pas renvoyé. La désactivation annule les demandes automatiques en attente. L’appareil de destination doit rouvrir SHOW+ pour recevoir une modification.
- Les groupes et favoris utilisent les identifiants de leur playlist. Si le fournisseur change les identifiants des chaînes, un élément ancien peut ne plus apparaître. Les sauvegardes de profil sont limitées à 350 Ko ; les profils qui dépassent cette limite peuvent toujours sauvegarder les réglages seuls.

## Vérification et mise en ligne

- Construire le site puis exécuter `node --test tests/worker-smoke.test.mjs`. Le test exerce l’association, la séparation des comptes, la capture, la restauration, la copie et les accusés de réception.
- Pour l’essai Android, lancer `node tests/tv-settings-device-fixture.mjs` sur le poste et exécuter `TvSettingsRoundTripTest` avec `tvSettingsFixtureUrl=http://10.0.2.2:4191`. Le Worker compilé reçoit les demandes d’une installation TV et d’une installation mobile fictives. Redémarrer le serveur local entre deux essais. Le parcours d’association tactile est couvert par `MobileSettingsRegressionTest#mobileBackupPairingOpensFromSettingsAndOffersCopyAndPortal`.
- Sur l’environnement à publier, vérifier que `VYRO_DB` pointe vers la base qui contient les installations SHOW+ (`show_installations`) et les licences du site. Appliquer les migrations `0004_tv_settings.sql`, `0005_tv_profiles.sql`, puis `0006_backup_device_kind.sql` sur cette même base. Publier le Worker avec Stripe désactivé.
- Vérifier la signature de l’APK SHOW+ 1.0.44 (build 342) contre l’APK publique 1.0.41. Le même APK prend en charge Android mobile, tablette et TV. L’espace client utilise le fichier privé de chaque plateforme quand il est disponible et propose sinon l’APK signé de la version 1.0.44 sur GitHub. Publier ce fichier avant la mise en ligne du site. Faire un essai avec un compte de test avant d’annoncer l’APK via le canal de mise à jour existant.
